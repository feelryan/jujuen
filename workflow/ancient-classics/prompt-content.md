根據指定古書某一章節中的「原文句子陣列」，將這些原文逐句轉換成 `Words` 陣列（包含繁體、簡體、拼音、注音與英文翻譯），**不得新增或刪除原文句子**。

⚠️ 重要：
- 所有輸出的 `t` 都必須精準對應輸入原文中的某一句或某一行，不可自行創作新的句子，也不可刪除句子。
- 不要加入「解說：」「說明：」「例如：」「總結：」等教學性或評論性敘述；本任務只做「原文 → 多語欄位」的轉換。
- 但是 `en` 欄位仍須根據語意情境，給出自然流暢的英文翻譯（可以意譯，不必逐字直譯）。

```json

```

其中 `original_lines` 是一個 JSON 陣列，每個元素是一句（或一行）原文，例如：

```json

  "子曰：學而時習之，不亦說乎？",

]
```

你的工作是：**逐句將上述原文轉成 `Words` 陣列**，並保持順序一致。

## 重要規則（輸出格式）

- **不要**包含任何非 JSON 格式的文字、說明或 ```json 標籤。
- 你的回應**必須**是一個 RFC 8259 標準的合法 JSON 陣列，最外層即為物件陣列。
- 不要在輸出中加入任何與「總數估計、批次數、規劃說明」相關的自然語言文字。
- 每一個元素都是一個 `Words` 物件，結構如下段所述。

## `Words` 物件結構與轉換規則

1. **嚴格對齊原文，禁止增刪**：
  - 對於 `original_lines` 陣列中的每一個元素，都必須產生對應的一個或多個 `Words` 物件。
  - 原則上，一個原文句子對應一個 `Words` 物件即可；若你覺得有必要，也可以將較長的句子切成 2 個以上較短的句子，但**不得把多個原文句子合併成一個**。
  - 不要在 `t` 中寫「此章主要說明…」「這句話的意思是…」等說明性語句。
2. **多語支援**：
   每個 `Words` 物件必須包含：
   - `t`：繁體中文原文句子或片語。
   - `c`：對應的簡體中文（維持原文內容，不要改成說明句）。
   - `p`：拼音，只針對句子中出現的漢字，使用空格分隔音節。
   - `z`：注音，只針對句子中出現的漢字，使用空格分隔每個字的注音。
   - `en`：依照語意情境，給出自然流暢的英文翻譯（可以是意譯，不必逐字直譯）。
3. **拼音和注音**：
   - 拼音與注音須根據整句意思為每個漢字選擇正確發音，避免機械式亂配音節。
   - 英文、數字、符號不需要拼音與注音。
4. **字詞分組 (`wg`)**：
   - 針對每個句子中「較關鍵、較難的原文字詞」，建立字詞群組。
   - 每個群組物件包含：
     - `t`：詞組的繁體中文（原文中的詞或短語）
     - `en`：詞組對應的英文解釋或翻譯
     - `ps`：詞性（例如 `N`, `V`, `Adj`, `Adv`, `Phrase` 等）。

## JSON 欄位縮寫定義

- `tag`: 建議對應的 HTML tag，例如：`h1`, `h2`, `h3`, `h4`, `ul`, `li`, `p` 等，用來表達層級與排版語氣。
- `t`: 繁體中文原文
- `c`: 對應的簡體中文原文
- `p`: 拼音（僅針對漢字）
- `z`: 注音（僅針對漢字）
- `en`: 英文翻譯
- `wg`: 字詞群組陣列，每個元素包含：
  - `t`: 詞組的繁體中文
  - `en`: 詞組對應的英文
  - `ps`: 詞性（例如 N, V, Adj, Adv, Phrase 等）
