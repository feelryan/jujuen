## 出題與批次規劃（請在內部思考，不要輸出規劃文字）

在開始實際輸出題目前，請先在「內部思考」完成以下步驟（規劃結果**不要**寫進輸出 JSON，僅用來指導出題）：

1. **分析教材範圍**：快速瀏覽整份 Markdown，列出它涵蓋的主要單元、子觀念與典型解題技巧。
2. **估計總題數**：根據內容份量與難度層次，心中估計一個「合理的總題目數量」以完整覆蓋教材（例如：較短的教材約 15–25 題、較長且單元多元的教材約 30–50 題以上）。
3. **規劃批次與每批題數**：
   - 依據總題數，心中規劃要分成幾個批次（例如 3–6 批）。
   - 為每一批分配大約的出題數量（例如每批 5–10 題，最後一批可稍作調整）。
4. ** coverage 規劃**：規劃一個大致的大綱：
   - 每一批主要覆蓋哪些單元或概念（例如：第 1 批偏重基礎定義與公式、第 2 批偏應用情境與文字題、第 3 批偏常見錯誤與陷阱…）。
   - 盡量讓每一批的題目各有側重，合起來能完整覆蓋整份教材。
5. **避免重複（跨批次）**：
   - 若 {batch_num} 為 1，專注在「建立基礎概念與典型題型」。
   - 若 {batch_num} 大於 1，假設你會額外收到一段由系統提供的「前幾批已涵蓋重點摘要」（例如 {previous_batches_summary}），
     在心中比對後，盡量避免和前幾批在「出題角度與具體情境」上高度重複。

再次強調：以上所有「估計總題數、批次數、每批題數與 coverage 規劃」的結果，

## 產出格式規則

1. **分句原則**：題目敘述與解析說明須以句號或自然語句為界進行分句，放入 `question` 或 `why` 陣列中。
2. **多語支援**：每一句需包含繁體 (t)、簡體 (c)、拼音 (p，空格區隔)、注音 (z，空格區隔) 及英文 (en)。
3. **拼音和注音**：拼音與注音須根據整句意思為每個漢字選擇正確發音，避免機械式亂配音節。
4. **字詞分組 (wg)**：針對每個分句，識別出具有特殊意義、對學生來說較抽象或不直覺的中文字詞群組，
   並提供該詞組的繁體中文 (t)、英文翻譯 (en) 及詞性 (ps)。
5. **解釋邏輯 (why)**：在 `why` 欄位中，以多句方式解釋：
   - 為什麼正確答案是正確的；
   - 為什麼其他選項是錯誤的；
   - 盡量提供直覺化的說明與常見錯誤提醒，同樣採中英對照並可分句。
6.  **選項標號 (options)**：`options` 為一個陣列，依照陣列順序對第 1、2、3、4 個選項依序加上 `(A) `、`(B) `、`(C) `、`(D) `⋯ 作為前綴。此前綴必須同時加在該選項的 `t` 與 `en` 字串開頭；若原本文字已有其它標號（例如 `A.`、`(1)` 等），請先移除再改用標準的 `(A) `、`(B) `⋯。不得出現重複或遺漏的標號，且除了加入標號外，請不要改變選項原本的語意。
7.  **答案格式 (answer)**：
  - 若為單選題（Single Choice / 單選題），`"answer"` 必須是一個單一大寫英文字母，例如 `"A"`、`"B"`，對應正確選項的標號。
  - 若為複選題（Multiple Choice / 複選題），`"answer"` 必須是一個由一個或多個大寫英文字母組成的字串，使用半形逗號分隔且不含空白，例如 `"A,B"` 或 `"B,D"`。
  - 禁止使用數字索引（例如 0,1,2 或 1,2,3⋯）或完整文字敘述來表示答案，必須只用選項標號字母。

---

## JSON 欄位縮寫定義

- `t`: 繁體中文
- `c`: 簡體中文
- `p`: 拼音
- `z`: 注音
- `en`: 英文
- `wg`: 字詞群組陣列，每個元素包含：
  - `t`: 詞組的繁體中文
  - `en`: 詞組對應的英文
  - `ps`: 詞性（例如 N, V, Adj, Adv 等）
