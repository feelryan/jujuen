根據上傳的國中教材 Markdown 內容（{subject}_{grade}_{term}.md）轉換成 `Words` 陣列的 JSON 檔案。

⚠️ 注意：教材可能很長，本次呼叫**只會處理其中一個片段**：

- 你會收到這是「第 {chunk_index} / {total_chunks} 片段」的資訊。
- 系統會在這份說明之後，附上「本片段對應的 Markdown 內容」。
- 請你**只處理這個片段**，將其中每一行 / 每一段適當切成多句，轉換成 `Words` 陣列的一部分。
- 最終完整的 `{subject}_{grade}_{term}.json`，會由系統把所有片段的 `Words` 陣列**依照片段順序串接起來**，你不需要在輸出中標註片段編號。

## 重要規則（輸出格式）

- **不要**包含任何非 JSON 格式的文字、說明或 ```json 標籤。
- 你的回應**必須**是一個 RFC 8259 標準的合法 JSON 陣列，最外層即為物件陣列。
- 不要在輸出中加入任何與「總數估計、批次數、規劃說明」相關的自然語言文字。

---

## 轉換格式規則

1. **分句原則**：題目敘述與解析說明須以句號或自然語句為界進行分句，放入陣列中。
2. **多語支援**：每一句需包含繁體 (t)、簡體 (c)、拼音 (p，空格區隔)、注音 (z，空格區隔) 及英文 (en)。
3. **拼音和注音**：拼音與注音須根據整句意思為每個漢字選擇正確發音，避免機械式亂配音節。請注意!只需要為漢字提供拼音和注音並空格區隔. 
4. **字詞分組 (wg)**：針對每個分句，識別出具有特殊意義、對學生來說較抽象或不直覺的中文字詞群組，並提供該詞組的繁體中文 (t)、英文翻譯 (en) 及詞性 (ps)。

### 分段處理與合併原則

- 每次呼叫僅處理一個 Markdown 片段（第 {chunk_index} / {total_chunks} 片段）。
- 你的輸出就是「這個片段所對應的全部 `Words` 陣列內容」。
- **不要**嘗試去推測或補上其他片段的內容，也不要加入「這是第幾片段」之類的說明文字。
- 系統會把各次呼叫輸出的 `Words` 陣列**依序串接**形成一個大的陣列，所以：
  - 你不需要在物件中加入片段號、全域索引等欄位。
  - 只要確保本次輸出的順序，與你掃描本片段 Markdown 內容的順序一致即可。


---

## JSON 欄位縮寫定義

- `tag`: 可能對應的HTML tag, ex: h1, h2, h3, h4, strong, ul, p
- `t`: 繁體中文
- `c`: 簡體中文
- `p`: 拼音(僅針對漢字)
- `z`: 注音(僅針對漢字)
- `en`: 英文
- `wg`: 字詞群組陣列，每個元素包含：
  - `t`: 詞組的繁體中文
  - `en`: 詞組對應的英文
  - `ps`: 詞性（例如 N, V, Adj, Adv 等）

---

## 產出格式

```json
[
  {
    "tag": "...",
    "t": "...",
    "c": "...",
    "p": "...",
    "z": "...",
    "en": "...",
    "wg": [
      {"t": "...", "en": "...", "ps": "..."}
    ]
  }
]
```
