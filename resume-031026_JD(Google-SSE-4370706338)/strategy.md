## 4. 常見追問與應對 | Likely Follow‑ups & Responses

- **Q: 你沒有直接設計晶片或資料中心硬體的經驗，如何勝任這個職位？**
  - **Q: You don't have direct experience designing chips or data center hardware; how will you handle this role?**
- **A**：雖然我不是硬體工程師，但我擅長構建「控制層（Control Plane）」軟體。在中華電信時，我負責整合感測器與警報硬體；在 Innova，我處理醫療設備的影像傳輸。我懂得如何透過 API 和驅動層與硬體溝通，並監控其健康狀態，這正是診斷工具的核心。
  - **A**: While I'm not a hardware engineer, I specialize in building "Control Plane" software. At Chunghwa Telecom, I integrated sensors and alert hardware; at Innova, I handled image transmission from medical devices. I understand how to communicate with hardware via APIs/drivers and monitor their health, which is the core of diagnostic tools.

- **Q: 你如何處理系統除錯（System Debugging）？**
  - **Q: How do you approach System Debugging?**
- **A**：我採用由上而下的方法。首先利用監控儀表板（如 GCP Cloud Monitoring）確認指標異常，接著分析分散式追蹤（Distributed Tracing）定位瓶頸服務，最後深入日誌（Logs）與代碼層級。我習慣建立自動化測試來重現問題，確保修復後不會回歸。
  - **A**: I use a top-down approach. First, I check monitoring dashboards (like GCP Cloud Monitoring) for metric anomalies, then analyze distributed tracing to locate bottleneck services, and finally dive into logs and code levels. I make it a habit to build automated tests to reproduce issues, ensuring no regressions after fixes.

## 5. 技術深挖提示（如適用） | Technical Deep‑Dive Prompts (if relevant)

針對 **System Programming & Diagnostics**，面試官可能會深挖以下主題：
For **System Programming & Diagnostics**, interviewers may deep-dive into:

1.  **GCP 架構與工具 (GCP Architecture & Tools)**
    - *Prompt*: "How would you design a tool to monitor the health of 10,000 servers?"
    - *Strategy*: Use your **GCP Architect** knowledge. Discuss Pub/Sub for ingestion, Dataflow for processing, and BigQuery/Cloud Monitoring for analysis.

2.  **Linux 系統基礎 (Linux System Fundamentals)**
    - *Prompt*: "A process is consuming 100% CPU. How do you debug it?"
    - *Strategy*: Mention tools like `top`, `htop`, `strace` (to see system calls), and analyzing `/proc` file system. (Review these commands).

3.  **自動化與腳本 (Automation & Scripting)**
    - *Prompt*: "How do you ensure a configuration change doesn't break the fleet?"
    - *Strategy*: Discuss **Canary Deployments**, Rollback strategies, and Infrastructure as Code (Terraform/Ansible concepts, even if you use custom scripts).

## 6. 常見陷阱與糾正 | Pitfalls & Corrections

- **陷阱：過度強調前端 UI 細節**
  - **Pitfall: Over-emphasizing frontend UI details.**
- **糾正**：此職位是 Diagnostics/Tools。即使你做過 React，請將重點放在「如何為內部使用者構建高效的儀表板」或「API 設計」，而非 CSS 或動畫。
  - **Correction**: This role is for Diagnostics/Tools. Even if you did React, focus on "how to build efficient dashboards for internal users" or "API Design," not CSS or animations.

- **陷阱：表現得像是一個純粹的「使用者」而非「建造者」**
  - **Pitfall: Acting like a pure "User" of cloud tools rather than a "Builder."**
- **糾正**：不要只說「我使用 GCP 部署」，要說「我設計了自動化流程來管理 GCP 資源」。強調你如何優化工具本身，而不僅僅是使用它們。
  - **Correction**: Don't just say "I use GCP to deploy." Say "I designed automation workflows to manage GCP resources." Emphasize how you optimized the tools themselves, not just used them.
